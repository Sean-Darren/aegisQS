# Migration plan: tender-audit front end to the four-module Smart QS MVP

_Inventory taken 4 November 2026. Planning document only; no implementation or deletion is part of this step._

## Source and decision boundary

`AGENTS.md`, `DESIGN.md` and `PRODUCT_BRIEF.md` define the new scope: drawing revision analysis, material forecasting and procurement timing, a versioned document hub, and Excel upload/check/diff. The brief identifies the hackathon P0 features, P1/P2 stretches and build stages. `TASK_PROMPTS.md`, which the brief cites for detailed task definitions, is not in the repository; the individual Task 03–09 labels below are therefore a recommended breakdown, while Task 10–12 follow the brief's stated stages. Do not start M1 until this plan is approved.

The working tree already contains uncommitted changes from the old scope, including the edited `AGENTS.md`/`DESIGN.md`, audit work, accessibility tests and dependency updates. M1 must preserve that state; do not reset it or treat the old implementation as a clean baseline. The user requested no code changes in this planning step.

**Classification:** KEEP means the existing implementation can be retained without domain changes; ADAPT means retain its useful mechanism but change its API, copy, styling or destination; DELETE means its behaviour serves only the dropped tender-audit scope. A placeholder is classified by its intended route, not as a completed feature. New files/routes required by `AGENTS.md` §8 are listed in the sequence below.
